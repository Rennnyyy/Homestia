# Test coverage — Homestia web app

`npm run test:coverage` in `src/Web/App` runs the Vitest suite through the
Angular unit-test builder with the v8 provider and enforces the floors below.

## Floors (enforced)

| Metric | Floor | Achieved |
|---|---|---|
| Statements | 75% | 78.48% |
| Branches | 72% | 74.47% |
| Functions | 65% | 68.77% |
| Lines | 80% | 85.30% |

Wiring lives in `angular.json` → `projects.spartan.architect.test.options`:

- `coverageInclude: ["src/app/**/*.ts"]` — **required**. Without it the builder
  drops the executed per-spec bundles before the source remap and every file
  reports 0%.
- `coverageExclude` — specs, plus `src/app/entities/**` (generated by
  `npm run generate-entities`; its correctness gate is `npm run codegen:check`).
- `coverageThresholds` — a ratchet: raise it when coverage rises, never lower it
  to make a red run green.
- Thresholds are enforced **only** when run with `--coverage` (`npm run
  test:coverage`); `npm test` stays fast and reports nothing.

Functions sit lowest on purpose: the remaining uncovered functions are template
event handlers and binding callbacks in the two large page components
(`properties.ts`, `rentals.ts`), not untested logic. The page state machines,
their guards and every route the pages call are covered.

## Doubles

Two of them, on purpose:

- `AletheiaHttpClientMock` (from `@rennnyyy/aletheia-core`) — records calls and
  answers from `BehaviorSubject`s. Fast for pages that subscribe once.
- A route-aware, **completing** double, local to `rentals.spec.ts` — required
  wherever the page fans out with `forkJoin` or awaits `lastValueFrom`: a
  `BehaviorSubject` never completes, so those pages would sit waiting forever.

`window.matchMedia` and `localStorage` are stubbed where the SDK theming
services are in the graph (jsdom provides neither).

## Traps already paid for

- The page writes `data-theme` from an `effect`: a root effect only runs on a
  change-detection cycle, so a spec must drive one (`fixture.detectChanges()`)
  before asserting the attribute.
- jsdom normalizes an inline `background-color` hex to `rgb(…)`.
- An `input.required()` read before `setInput` throws NG0950.
- i18n loading is the SDK's `TranslocoHttpLoader` (`@rennnyyy/aletheia-core`) —
  the app no longer carries a loader of its own, so there is no local spec for it;
  core's suite owns that behaviour.

## End-to-end and visual baselines

`npm run test:e2e` runs Playwright against a **running host** (the host serves
both the facade and the API):

```
dotnet run --project ../../Program --no-launch-profile --urls http://localhost:5081
E2E_BASE_URL=http://localhost:5081 npm run test:e2e          # compare
E2E_BASE_URL=http://localhost:5081 npm run test:e2e:update   # regenerate
```

The suite expects a **freshly started host** — the in-memory repository is empty
then, and the baselines were taken on that empty state. A long-running host
accumulates records, which shifts the table's masked height and diffs the
baseline for reasons that have nothing to do with the code. Start a new host (a
new port counts) before comparing or regenerating.

One test per route (home, properties, rentals) waits for the route component,
`networkidle` and `document.fonts.ready`, then compares the viewport at
`maxDiffPixelRatio: 0.01`. The ratio is a guard, not a comfort: at 2% a
re-designed header and a 32px-wider rail slid past unnoticed, so it is kept just
above antialiasing noise. Table **rows are masked** (`aletheia-entity-table
tbody`): they come from the backend and change per host start, so the baseline
captures the look — chrome, typography, spacing, colours — not today's data. The
baselines (`e2e/*.spec.ts-snapshots/`) are **committed** — they are the proof
that a migration or a dependency bump changed the code and not the look.

Two further tests cover the **phone chrome** (`viewport 390×844`). They assert
geometry rather than pixels: the closed drawer sits entirely off-canvas and the
page does not scroll sideways, and the opened drawer keeps its content inside
its own box (a rail whose chrome overflows is visible even while the drawer is
shut, because the panel rests exactly one width off the left edge). Their
baselines — `mobile-properties`, `mobile-drawer-open` — record the bar and the
drawer at that width.
`dotnet test` is the backend half (`tests/`), and `npm run codegen:check` gates
the generated entity surface.

Playwright is deliberately **not** a CI gate: it needs a live backend and browser
binaries, so it runs locally before a release.
